Lab09: SQL injection UNION attack, retrieving data from other tables

Nivel Practitioner
Tipo de SQLi SQL Injection UNION-based (extracción de datos)

Objetivo

Obtener todos los nombres de usuario (usernames) y contraseñas (passwords) de la tabla users mediante un ataque SQL Injection basado en UNION.

Vulnerabilidad

El parámetro de categoría de productos se concatena directamente en la consulta SQL sin validación ni sanitización. La aplicación devuelve los resultados directamente en la respuesta HTTP, lo que permite modificar la consulta original y unirla con otra consulta que acceda a la tabla users.

Para este laboratorio, se sabe que existe una tabla llamada users con las columnas username y password. El objetivo es extraer toda la información de esta tabla.

Procedimiento

  1. Partir del número de columnas conocido. De laboratorios anteriores sabemos que la consulta original devuelve 2 columnas.
  2. Interceptar la petición con Burp Suite al seleccionar una categoría (por ejemplo, "Gifts") y enviarla al Repeater. 
    GET /filter?category=Gifts HTTP/1.1
  3. Confirmar qué columnas aceptan texto con un payload de prueba: 
    ' UNION SELECT 'abc','def'--

    Si ambas columnas muestran 'abc' y 'def' en la respuesta, significa que ambas pueden utilizarse para extraer datos de texto.

  4. Construir el payload para extraer datos de la tabla users: 
    ' UNION SELECT username, password FROM users--
  5. Enviar la petición y observar la respuesta HTTP. En ella aparecerán todos los nombres de usuario y contraseñas almacenados en la tabla users.
  6. Identificar las credenciales del usuario administrator en la lista de resultados.
  7. Iniciar sesión en la aplicación con las credenciales obtenidas para resolver el laboratorio.

Payloads utilizados

Payload de prueba

' UNION SELECT 'abc','def'--

Payload de extracción

' UNION SELECT username, password FROM users--

Explicación de los payloads

  • ': Cierra la cadena de la categoría original.
  • UNION SELECT: Combina los resultados de la consulta legítima con los de nuestra consulta maliciosa.
  • 'abc','def': Valores de prueba para confirmar que ambas columnas aceptan texto y se muestran en la respuesta.
  • username, password: Nombres de las columnas de la tabla users que queremos extraer.
  • FROM users: Indica la tabla objetivo que contiene las credenciales.
  • --: Comenta el resto de la consulta original para evitar errores de sintaxis.

Consulta final ejecutada

SELECT * FROM products WHERE category = '' UNION SELECT username, password FROM users--' AND released = 1

La consulta devuelve los productos de la categoría original más los nombres de usuario y contraseñas de la tabla users, que se renderizan en la página web.

Ejemplo de respuesta esperada

administrator: 8fg5h2j1
carlos: password123
wiener: passw0rd

Verificación del ataque

Al enviar el payload ' UNION SELECT username, password FROM users--, la respuesta HTTP muestra todas las credenciales de los usuarios almacenadas en la base de datos. Esto confirma que:

  • La inyección SQL fue exitosa.
  • Se ha accedido a una tabla diferente a la original (users).
  • Se ha comprometido la confidencialidad de los datos de autenticación.

Con las credenciales del administrador obtenidas, se accede al panel de administración, demostrando el impacto crítico de esta vulnerabilidad.

Resultado esperado: El laboratorio se resuelve correctamente al iniciar sesión como administrator y aparece el mensaje "Congratulations, you solved the lab!" en la interfaz de PortSwigger Academy.

Mitigación recomendada

Consultas Preparadas (Parameterized Queries)

Implementar consultas parametrizadas es la defensa principal. Al usar parámetros en lugar de concatenar cadenas, los valores inyectados por el usuario se tratan como simples datos y no como parte del código SQL. Esto bloquea la posibilidad de inyectar un UNION SELECT.

SELECT * FROM products WHERE category = ? AND released = 1

Principio de Menor Privilegio

La cuenta de base de datos usada por la aplicación no debe tener permisos para leer tablas sensibles como users. Idealmente, la cuenta de la aplicación solo debería tener acceso a las tablas necesarias para su funcionamiento (por ejemplo, la tabla products).

Validación de Entradas

Permitir solo valores esperados para el parámetro de categoría (lista blanca). Por ejemplo, limitar las categorías a un conjunto predefinido.

Gestión de Errores Controlada

Configurar la aplicación para que no muestre mensajes de error detallados al usuario, evitando dar pistas sobre la estructura de la base de datos.

Escapado de Caracteres Especiales

Como defensa adicional en profundidad, escapar correctamente los caracteres especiales como comillas simples.
