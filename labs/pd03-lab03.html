Lab03: SQL injection attack, querying the database type and version on Oracle

Nivel Practitioner
Tipo de SQLi UNION-based SQLi (Inyección basada en el operador UNION para enumeración de base de datos)

Objetivo

Utilizar un ataque de inyección SQL para recuperar la versión de la base de datos de Oracle.

Vulnerabilidad

La vulnerabilidad reside en el filtro de categoría. Al usar UNION, podemos "pegar" los resultados de una segunda consulta a la consulta original.

Particularidades de Oracle:

  • Cada SELECT debe tener una cláusula FROM. Si quieres consultar algo que no requiere una tabla real, debes usar la tabla integrada DUAL.
  • Para obtener la versión, se debe consultar la tabla/vista v$version.

Procedimiento

  1. Interceptar la petición al seleccionar una categoría (por ejemplo, "Accessories") y enviarla al Repeater.
  2. Determinar el número de columnas probando payloads de UNION SELECT: 
    ' UNION SELECT NULL FROM DUAL--

    Si da error, se añaden más NULL hasta que la página cargue normalmente. En Oracle, se requiere la tabla DUAL.

    ' UNION SELECT NULL, NULL FROM DUAL--

    Cuando la página carga sin errores, se ha determinado que la consulta original devuelve 2 columnas.

  3. Verificar qué columna acepta texto, reemplazando los NULL por strings: 
    ' UNION SELECT 'abc', 'def' FROM DUAL--

    Si esto funciona, ambas columnas aceptan texto.

  4. Extraer la versión inyectando la consulta real para Oracle: 
    ' UNION SELECT banner, NULL FROM v$version--

    El campo banner en la tabla v$version contiene la información de la versión.

Payload utilizado

' UNION SELECT banner, NULL FROM v$version--

Explicación del payload

  • ': Cierra la cadena de la categoría original.
  • UNION SELECT: Combina los resultados de la consulta legítima con los de la consulta maliciosa.
  • banner: Es el nombre de la columna en Oracle que almacena la descripción de la versión.
  • NULL: Se usa para completar el número de columnas requerido (ya que la consulta original tiene 2 columnas, nuestra unión debe tener 2).
  • FROM v$version: Tabla del sistema en Oracle que contiene la información de versión.
  • --: Comenta el resto de la consulta original para evitar errores de sintaxis.

Consulta final ejecutada

SELECT * FROM products WHERE category = '' UNION SELECT banner, NULL FROM v$version--' AND released = 1

La consulta devuelve los productos de la categoría original más los resultados de la consulta a v$version, mostrando la versión de Oracle en la respuesta HTTP.

Verificación del ataque

Al enviar el payload ' UNION SELECT banner, NULL FROM v$version--, la respuesta HTTP muestra, junto a los productos de la categoría, la información de la versión de Oracle, típicamente con un formato como:

Oracle Database 11g Express Edition Release 11.2.0.2.0 - 64bit Production

Esto confirma que la inyección SQL fue exitosa y que se ha podido enumerar información del sistema de la base de datos.

Mitigación recomendada

Consultas Preparadas (Parameterized Queries)

Implementar consultas parametrizadas es la defensa principal. Al usar parámetros, los comandos SQL inyectados se tratan como simples datos de texto y no como código ejecutable.

SELECT * FROM products WHERE category = ? AND released = 1

Principio de Menor Privilegio

La cuenta de base de datos que usa la aplicación web no debería tener permisos para leer tablas del sistema como v$version a menos que sea estrictamente necesario.

Validación de Entradas

Implementar listas blancas para el parámetro de categoría, permitiendo solo valores predefinidos.

Ocultar errores de base de datos

Configurar la aplicación para que no muestre errores detallados al usuario, evitando dar pistas sobre la estructura de la base de datos.
