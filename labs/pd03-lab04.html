Lab04: SQL injection attack, querying the database type and version on MySQL and Microsoft

Nivel Practitioner
Tipo de SQLi SQL Injection basado en UNION

Objetivo

Mostrar la cadena con la versión de la base de datos para resolver el laboratorio.

Vulnerabilidad

El filtro de categoría de productos es vulnerable a inyecciones SQL. La aplicación no valida ni maneja la entrada del usuario en el parámetro category, lo que permite al atacante modificar la consulta SQL original.

Para MySQL y Microsoft SQL Server, la función que devuelve la versión es @@version.

Procedimiento

  1. Iniciar Burp Suite y activar la interceptación en la pestaña Proxy. Seleccionar una categoría (por ejemplo, "Accessories") y enviar la petición al Repeater.
  2. Determinar el número de columnas probando payloads de UNION SELECT: 
    ' UNION SELECT NULL--

    Si da error, se añaden más NULL hasta que la página cargue normalmente:

    ' UNION SELECT NULL,NULL--

    Cuando la página carga sin errores, se ha determinado que la consulta original devuelve 2 columnas.

  3. Confirmar que podemos observar resultados usando valores de prueba: 
    ' UNION SELECT 'abc','def'#

    En MySQL, el carácter de comentario puede ser # además de --.

  4. Extraer la versión utilizando la función @@version: 
    ' UNION SELECT @@version, NULL#

    La función @@version devuelve la versión completa de MySQL o Microsoft SQL Server.

Payloads utilizados

Payload 1 (prueba de columnas)

' UNION SELECT 'abc','def'#

Payload 2 (extracción de versión)

' UNION SELECT @@version, NULL#

Explicación del payload

  • ': Cierra la cadena de la categoría original.
  • UNION SELECT: Combina los resultados de la consulta legítima con los de la consulta maliciosa.
  • @@version: Variable global en MySQL y Microsoft SQL Server que contiene la información de la versión.
  • NULL: Completa el número de columnas requerido (2 columnas en total).
  • #: Carácter de comentario en MySQL. Anula el resto de la consulta original.

Explicación detallada del payload de prueba

  • ' UNION SELECT 'abc','def'#: Las cadenas 'abc' y 'def' se usan para confirmar qué columnas aceptan texto y se muestran en la respuesta. Si vemos estas cadenas en la página, sabemos que podemos inyectar datos alfanuméricos en esas posiciones.

Consulta final ejecutada

SELECT * FROM products WHERE category = '' UNION SELECT @@version, NULL#' AND released = 1

La consulta devuelve los productos de la categoría original más el resultado de @@version, mostrando la versión de la base de datos en la respuesta HTTP.

Verificación del ataque

Al enviar el payload ' UNION SELECT @@version, NULL#, la respuesta HTTP muestra, junto a los productos de la categoría, la información de la versión de MySQL, típicamente con un formato como:

8.0.27-0ubuntu0.20.04.1

Esto confirma que la inyección SQL fue exitosa y que se ha podido enumerar información del sistema de la base de datos.

Mitigación recomendada

Consultas Preparadas (Parameterized Queries)

Implementar consultas parametrizadas es la defensa principal. Al usar parámetros, los comandos SQL inyectados se tratan como simples datos de texto y no como código ejecutable.

SELECT * FROM products WHERE category = ? AND released = 1

Validación de entrada

Permitir solo caracteres esperados para el parámetro de categoría (lista blanca).

Ocultar errores de base de datos

No mostrar detalles de errores al usuario. Configurar mensajes genéricos y guardar los detalles en logs internos.

Mínimos privilegios

La cuenta de base de datos debe tener permisos estrictamente necesarios, limitando el acceso a tablas del sistema.
