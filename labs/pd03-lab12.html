Lab12: Blind SQL injection with conditional responses (data extraction)

Nivel Practitioner
Tipo de SQLi Blind SQL Injection Boolean-based con extracción de información

Objetivo

Extraer la contraseña del usuario administrator utilizando una técnica de SQL Injection ciega basada en respuestas condicionales (aparición del mensaje "Welcome back" en la página).

Vulnerabilidad

La cookie TrackingId es vulnerable a inyección SQL. La aplicación no muestra directamente los resultados de las consultas, pero cambia el contenido de la página dependiendo de si la condición SQL es verdadera o falsa, mostrando el mensaje "Welcome back" cuando la condición es verdadera.

Esto permite a un atacante realizar múltiples consultas booleanas para descubrir la contraseña del usuario administrador carácter por carácter, mediante un proceso de inferencia.

A diferencia del laboratorio anterior, aquí se realiza la extracción completa de la contraseña utilizando herramientas como Burp Intruder para automatizar el proceso.

Procedimiento

  1. Interceptar la petición con Burp Suite Proxy y enviarla al Repeater. 
    GET / HTTP/1.1
Cookie: TrackingId=xyz123
  2. Identificar la cookie vulnerable TrackingId como punto de inyección.
  3. Confirmar la vulnerabilidad probando condiciones booleanas: 
    TrackingId=xyz' AND '1'='1

    Se observa el mensaje "Welcome back".

    TrackingId=xyz' AND '1'='2

    El mensaje "Welcome back" desaparece, confirmando la vulnerabilidad.

  4. Determinar la longitud de la contraseña del usuario administrator utilizando consultas SQL: 
    TrackingId=xyz' AND (SELECT 'a' FROM users WHERE username='administrator' AND LENGTH(password)=1)='a

    Se incrementa el número (2, 3, 4, etc.) hasta que el mensaje "Welcome back" aparece. Cuando aparece, se ha encontrado la longitud exacta.

    Para este laboratorio, la contraseña tiene 20 caracteres.

  5. Utilizar la función SUBSTRING() para comparar cada carácter de la contraseña: 
    TrackingId=xyz' AND (SELECT SUBSTRING(password,1,1) FROM users WHERE username='administrator')='a
  6. Automatizar el proceso mediante Burp Intruder:
    • Enviar la petición al Intruder.
    • Marcar como payload la posición del carácter (por ejemplo, 1,1) y el carácter a probar.
    • Configurar el tipo de payload: números para la posición y caracteres para el valor.
    • Probar caracteres alfanuméricos (a-z, 0-9).
  7. Identificar los caracteres correctos: Cuando la respuesta del servidor muestre el mensaje "Welcome back", se confirma que el carácter probado es correcto.
  8. Repetir el proceso para cada posición (1 a 20) hasta obtener la contraseña completa.
  9. Iniciar sesión con las credenciales obtenidas del usuario administrator.

Payloads utilizados

Payload para determinar longitud

xyz' AND (SELECT 'a' FROM users WHERE username='administrator' AND LENGTH(password)=20)='a

Payload para extraer caracteres

xyz' AND (SELECT SUBSTRING(password,1,1) FROM users WHERE username='administrator')='a

Explicación de los payloads

  • xyz': Cierra la cadena original de la cookie TrackingId.
  • AND: Permite agregar una condición adicional a la consulta SQL.
  • (SELECT 'a' FROM users WHERE username='administrator' AND LENGTH(password)=20): Subconsulta que devuelve 'a' solo si existe el usuario administrator y su contraseña tiene longitud 20.
  • ='a': Compara el resultado de la subconsulta con 'a'. Si la subconsulta devuelve 'a', la condición es verdadera y aparece "Welcome back".
  • SUBSTRING(password,1,1): Extrae el primer carácter de la contraseña. Se cambia el primer número para cada posición (2,1; 3,1; etc.).
  • ='a': Compara el carácter extraído con el carácter que se está probando.

Proceso con Burp Intruder

  • Payload position 1: Número de posición (1-20).
  • Payload position 2: Carácter a probar (a-z, 0-9).
  • Resource pool: Configurar con 1 hilo para evitar interferencias por delays.
  • Filtro de resultados: Buscar respuestas que contengan "Welcome back".

Ejemplo de contraseña extraída: 8fg5h2j1k4m9p3q7r2s5

Verificación del ataque

La vulnerabilidad se confirma cuando se logra reconstruir la contraseña completa del usuario administrator mediante las respuestas condicionales.

Una vez obtenida la contraseña (por ejemplo, "8fg5h2j1k4m9p3q7r2s5"), se introduce en el formulario de login junto con el usuario "administrator" y se accede al panel de administración, demostrando que:

  • La inyección SQL ciega permite extraer información sensible sin ver resultados directos.
  • La técnica booleana es efectiva incluso cuando la aplicación no muestra datos.
  • Herramientas como Burp Intruder automatizan eficientemente el proceso de extracción.

Resultado esperado: El laboratorio se resuelve correctamente al iniciar sesión como administrator y aparece el mensaje "Congratulations, you solved the lab!" en la interfaz de PortSwigger Academy.

Mitigación recomendada

Consultas Preparadas (Parameterized Queries)

Implementar consultas parametrizadas es la defensa principal. Al usar parámetros, los valores inyectados se tratan como datos y no como parte de la estructura SQL, bloqueando cualquier intento de inyección.

SELECT * FROM tracking WHERE id = ?

Validación de Entradas

Validar estrictamente el formato del TrackingId. Si sigue un patrón predecible (alfanumérico de longitud fija), rechazar cualquier valor que no cumpla con ese patrón.

Eliminar Respuestas Condicionales

Modificar la aplicación para que no muestre contenido diferente basado en resultados de consultas a la base de datos. El mensaje "Welcome back" debería mostrarse de forma consistente o no mostrarse en absoluto, independientemente del TrackingId.

Límite de Intentos

Implementar mecanismos de rate limiting que detecten y bloqueen múltiples peticiones con diferentes TrackingId en un corto período de tiempo, dificultando ataques de fuerza bruta como los realizados con Intruder.

Web Application Firewall (WAF)

Implementar un WAF que detecte y bloquee patrones de inyección SQL, incluyendo intentos de manipulación de cookies y subconsultas condicionales.

Principio de Menor Privilegio

La cuenta de base de datos utilizada por la aplicación debe tener permisos mínimos, limitando el acceso a las tablas necesarias.
