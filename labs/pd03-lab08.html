Lab08: SQL injection UNION attack, finding a column containing text

Nivel Practitioner
Tipo de SQLi SQL Injection UNION-based (con prueba de tipo de datos)

Objetivo

Descubrir qué columna(s) son compatibles con datos de tipo string (texto). El laboratorio proporciona un valor específico que debe aparecer en la respuesta, por ejemplo: 'nB5HqL'.

Vulnerabilidad

El parámetro de categoría de productos se concatena directamente en la consulta SQL sin validación ni sanitización. La aplicación devuelve los resultados directamente en la respuesta HTTP, lo que permite realizar ataques UNION para identificar los tipos de datos de cada columna.

Una vez conocido el número de columnas (determinado en el laboratorio anterior), es necesario identificar qué columna(s) aceptan datos de tipo texto, ya que será a través de esas columnas donde se puedan visualizar los datos extraídos en ataques posteriores.

Procedimiento

  1. Partir del número de columnas conocido. Del laboratorio anterior sabemos que la consulta original devuelve 2 columnas.
  2. Interceptar la petición con Burp Suite y enviarla al Repeater. 
    GET /filter?category=Gifts HTTP/1.1
  3. Probar con un payload que coloque un string en la primera columna y NULL en las demás: 
    ' UNION SELECT 'abcdef', NULL--

    Si la primera columna acepta texto, veremos la cadena 'abcdef' en algún lugar de la respuesta.

  4. Si no aparece, probar con el string en la segunda columna: 
    ' UNION SELECT NULL, 'abcdef'--
  5. Identificar la columna que muestra el texto. Para este laboratorio, se encuentra que la segunda columna es la que acepta texto y muestra el valor inyectado.
  6. Reemplazar 'abcdef' por el valor proporcionado en el laboratorio (por ejemplo, 'nB5HqL'): 
    ' UNION SELECT NULL, 'nB5HqL'--
  7. Verificar que el valor aparece en la respuesta, resolviendo así el laboratorio.

Payloads utilizados

Payload de prueba (primera columna)

' UNION SELECT 'abcdef', NULL--

Payload de prueba (segunda columna)

' UNION SELECT NULL, 'abcdef'--

Payload final con el valor del laboratorio

' UNION SELECT NULL, 'nB5HqL'--

Explicación de los payloads

  • ': Cierra la cadena de la categoría original.
  • UNION SELECT: Combina los resultados de la consulta legítima con los de nuestra consulta maliciosa.
  • 'abcdef': Cadena de texto de prueba que colocamos en diferentes posiciones para identificar qué columna acepta strings.
  • NULL: Se usa en las columnas que no estamos probando para mantener el número correcto de columnas sin generar errores de tipo.
  • 'nB5HqL': Valor específico proporcionado por el laboratorio que debe aparecer en la respuesta.
  • --: Comenta el resto de la consulta original para evitar errores de sintaxis.

Proceso de identificación

  • Primera prueba: ' UNION SELECT 'abcdef', NULL-- → El texto no aparece en la respuesta (la columna 1 probablemente es numérica).
  • Segunda prueba: ' UNION SELECT NULL, 'abcdef'-- → El texto 'abcdef' aparece en la respuesta (la columna 2 acepta texto).
  • Conclusión: La columna 2 es compatible con strings.

Verificación del ataque

Al enviar el payload con el valor proporcionado en la columna correcta, la respuesta HTTP muestra ese valor específico en la página, típicamente en la sección donde se renderizan los productos o en algún elemento de la interfaz.

Por ejemplo, si el laboratorio proporciona el valor 'nB5HqL', al inyectar ' UNION SELECT NULL, 'nB5HqL'-- veremos ese texto aparecer en la respuesta, confirmando que:

  • La columna 2 acepta datos de tipo texto.
  • Podemos inyectar y visualizar strings arbitrarios en esa posición.
  • El laboratorio se resuelve porque el valor requerido aparece en la respuesta.

Resultado esperado: El laboratorio se resuelve correctamente y aparece el mensaje "Congratulations, you solved the lab!" en la interfaz de PortSwigger Academy.

Mitigación recomendada

Consultas Preparadas (Parameterized Queries)

Implementar consultas parametrizadas es la defensa principal. Al usar parámetros, los valores inyectados se tratan como datos y no como parte de la estructura SQL.

SELECT * FROM products WHERE category = ? AND released = 1

Validación Estricta de Entradas

El parámetro de categoría debe aceptar únicamente valores válidos predefinidos (lista blanca). Por ejemplo, solo permitir las categorías existentes: 'Gifts', 'Lifestyle', 'Accessories', etc.

Principio de Menor Privilegio

La cuenta de base de datos utilizada por la aplicación debe tener permisos mínimos. Solo debe acceder a las tablas necesarias para mostrar productos y categorías, limitando el acceso a información sensible.

Gestión de Errores Controlada

Configurar la aplicación para que no muestre mensajes de error detallados al usuario. Los errores deben registrarse internamente.

Tipado Fuerte en la Aplicación

En el código de la aplicación, forzar que los parámetros de entrada tengan el tipo esperado (por ejemplo, enteros para IDs, strings con validación de formato).
