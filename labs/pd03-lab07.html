Lab07: SQL injection UNION attack, determining the number of columns returned by the query

Nivel Practitioner
Tipo de SQLi SQL Injection UNION-based

Objetivo

El objetivo inicial es descubrir cuántas columnas devuelve la consulta original, porque el operador UNION solo funciona si ambas consultas tienen el mismo número y tipo de columnas.

Vulnerabilidad

El filtro de categorías de productos no valida ni sanitiza correctamente la entrada del usuario antes de construir la consulta SQL. Esto permite inyectar payloads que modifiquen la consulta original y, mediante el operador UNION, intentar concatenar resultados.

Para que un ataque UNION tenga éxito, es necesario conocer el número exacto de columnas que devuelve la consulta original. Esto se logra mediante inyecciones progresivas de NULL hasta que la consulta se ejecute sin errores.

Procedimiento

  1. Acceder al laboratorio e interactuar con el filtro seleccionando cualquier categoría de productos (por ejemplo, "Gifts").
  2. Interceptar la petición con Burp Suite y enviarla al Repeater. 
    GET /filter?category=Gifts HTTP/1.1
  3. Probar con un payload de UNION SELECT NULL para determinar el número de columnas: 
    ' UNION SELECT NULL--

    Si la consulta original tiene más de una columna, esta inyección provocará un error porque el número de columnas no coincide.

  4. Incrementar progresivamente el número de NULL hasta que la página cargue sin errores: 
    ' UNION SELECT NULL,NULL--
    ' UNION SELECT NULL,NULL,NULL--

    Cuando la respuesta HTTP 200 contiene contenido normal (sin errores de base de datos), se ha encontrado el número correcto de columnas.

  5. Verificar que con 2 NULL la consulta funciona correctamente, indicando que la consulta original devuelve 2 columnas.

Payload utilizado

' UNION SELECT NULL,NULL--

Explicación del payload

  • ': Cierra la cadena de la categoría original.
  • UNION SELECT: Combina los resultados de la consulta legítima con los de nuestra consulta maliciosa.
  • NULL: Se usa para completar el número de columnas requerido. NULL es un valor universal que no genera conflictos de tipo de datos.
  • NULL,NULL: Cada NULL representa una columna ficticia. Para este laboratorio, se determina que la consulta original tiene 2 columnas.
  • --: Comenta el resto de la consulta original para evitar errores de sintaxis.

Proceso de determinación

  • ' UNION SELECT NULL--: Error (número incorrecto de columnas).
  • ' UNION SELECT NULL,NULL--: Éxito (la consulta se ejecuta correctamente).
  • Conclusión: La consulta original devuelve 2 columnas.

Consulta final ejecutada

SELECT * FROM products WHERE category = '' UNION SELECT NULL,NULL--' AND released = 1

La consulta se ejecuta sin errores porque ambas partes del UNION devuelven 2 columnas. Esto confirma que el número de columnas es 2 y prepara el terreno para futuros ataques UNION donde se extraerá información específica.

Verificación del ataque

Al enviar el payload ' UNION SELECT NULL,NULL--, la respuesta HTTP 200 contiene la página con los productos de la categoría, sin errores de base de datos. Esto confirma que la consulta original devuelve exactamente 2 columnas.

Si se prueba con un número incorrecto de columnas (por ejemplo, 1 o 3), la base de datos generará un error similar a:

"Internal Server Error" o "The used SELECT statements have a different number of columns"

La ausencia de errores con 2 NULL confirma el número exacto de columnas.

Mitigación recomendada

Consultas Preparadas (Parameterized Queries)

Implementar consultas parametrizadas es la defensa principal. Al usar parámetros en lugar de concatenar cadenas, los valores inyectados por el usuario se tratan como simples datos y no como parte del código SQL.

SELECT * FROM products WHERE category = ? AND released = 1

Validación de entrada

Permitir solo valores esperados para el parámetro de categoría (lista blanca). Por ejemplo, limitar las categorías a un conjunto predefinido.

Gestión de Errores Controlada

Configurar la aplicación para que no muestre mensajes de error detallados al usuario. Los errores de base de datos deben registrarse internamente, mientras que al usuario se le muestra un mensaje genérico.

Principio de menor privilegio

La cuenta de base de datos utilizada por la aplicación debe tener permisos mínimos, limitando el acceso solo a las tablas necesarias.
