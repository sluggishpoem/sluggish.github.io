ROAD TO HALL OF FAME · SQL INJECTION

Introducción

La Inyección SQL (SQLi) se mantiene como una de las vulnerabilidades más persistentes y peligrosas desde hace más de dos décadas. Esta vulnerabilidad permite a un atacante interferir con las consultas que una aplicación realiza a su base de datos, lo que puede resultar en el acceso no autorizado a datos sensibles, la modificación de registros e incluso la toma total del control del servidor de base de datos.

El presente módulo tiene como objetivo documentar de manera técnica y estructurada la resolución de diversos escenarios de vulnerabilidad SQLi, utilizando los laboratorios oficiales de PortSwigger (Web Security Academy). A través del uso de herramientas de interceptación profesional como Burp Suite, se analizarán diferentes vectores de ataque, desde los más directos (In-band) hasta técnicas avanzadas de inferencia (Blind) y fuera de banda (Out-of-band).

Marco Teórico

Funcionamiento de bases de datos relacionales

Las bases de datos relacionales (RDBMS) organizan los datos en tablas con filas y columnas, relacionadas entre sí mediante claves. Las aplicaciones web suelen interactuar con estas bases de datos para almacenar y recuperar información dinámica (usuarios, productos, configuraciones). El motor de la base de datos interpreta las instrucciones enviadas por la aplicación para ejecutar operaciones CRUD (Create, Read, Update, Delete).

Consultas SQL básicas

SQL (Structured Query Language) es el lenguaje estándar para la gestión de estas bases de datos. Para entender SQLi, es fundamental comprender comandos clave:

  • SELECT: Utilizado para recuperar datos de una o más tablas.
  • WHERE: Cláusula de filtrado que condiciona qué registros se ven afectados.
  • UNION: Operador que permite combinar los resultados de dos o más sentencias SELECT en un solo conjunto de resultados. Es la base de los ataques Union-based.
  • Comentarios: Dependiendo del motor (MySQL: -- o #, PostgreSQL: --, Oracle: --), sirven para anular el resto de una consulta legítima.

¿Qué es SQL Injection?

La Inyección SQL es una vulnerabilidad de seguridad web que ocurre cuando una aplicación permite que datos proporcionados por el usuario (entradas en formularios, parámetros URL, cookies) se concatenen directamente en una consulta SQL sin la debida validación o parametrización. Esto permite a un atacante "inyectar" comandos SQL propios que alteran la lógica original de la consulta programada por el desarrollador.

Clasificación de ataques SQLi

Ataque Descripción
In-band (Classic) Es el tipo más común y directo, donde el atacante utiliza el mismo canal de comunicación para lanzar el ataque y recoger los resultados. Incluye Union-based y Error-based.
Blind (Inferencial) Ocurre cuando la aplicación no devuelve datos directamente ni muestra errores detallados. El atacante debe "adivinar" la información mediante preguntas binarias (Boolean-based o Time-based).
Out-of-band (OOB) Técnica avanzada utilizada cuando no hay respuesta directa ni se pueden realizar inferencias por tiempo. El ataque obliga a la base de datos a realizar una solicitud externa (DNS o HTTP) a un servidor controlado por el atacante.

Impacto en la Tríada CIA

  • Confidencialidad: Es el impacto más frecuente. Los atacantes pueden extraer información privada (contraseñas, datos bancarios, datos de clientes).
  • Integridad: Un atacante puede usar comandos como UPDATE, INSERT o DELETE para corromper la información, alterar precios de productos o cambiar permisos de usuarios.
  • Disponibilidad: Mediante el borrado de tablas o el consumo excesivo de recursos, el atacante puede hacer que la aplicación sea inoperable.

Relación con OWASP Top 10

La Inyección SQL forma parte de la categoría A03:2021 – Injection (tercer lugar del top), ocupando históricamente los primeros lugares en el ranking de riesgos de seguridad en aplicaciones web debido a su alta prevalencia y severidad de impacto.

Tipos de Payloads

Los payloads son fragmentos de código malicioso diseñados para explotar la vulnerabilidad. Ejemplos comunes:

  • ' OR 1=1--: Para saltar autenticaciones.
  • ' UNION SELECT username, password FROM users--: Para extraer credenciales.
  • '; IF (1=1) WAITFOR DELAY '0:0:10'--: Para probar inyecciones ciegas por tiempo en SQL Server.

Principios de defensa

  • Sentencias Preparadas (Consultas Parametrizadas): Es la defensa principal. Separa el código SQL de los datos proporcionados por el usuario.
  • Validación de Entradas (Lista Blanca): Permitir solo caracteres y formatos conocidos y esperados.
  • Principio de Menor Privilegio: Configurar la cuenta de la base de datos con los permisos mínimos necesarios.
  • Uso de Procedimientos Almacenados: Siempre que se implementen de forma segura (sin concatenación interna).
